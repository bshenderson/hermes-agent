# Bounded CLI startup and deferred mapped secrets

The GXTD-900 opt-in is profile-local `secrets.lazy: true`. Existing profiles remain eager by default. Only mapped 1Password credentials are deferred; other enabled sources keep their explicit startup role. A home-lab command source producing local non-secret endpoint/email metadata remains eager. Do not enable arbitrary bulk sources expecting this feature to make their network work lazy.

`secrets.startup_names` maps an explicit CLI surface to credentials required before it serves, for example `gateway: [API_SERVER_KEY]` and `dashboard: [API_SERVER_KEY]`. Required names must be supplied by the configured source; missing source values refuse startup before staged values are published. Ordinary chat resolves provider credentials through the selected provider's native scoped lookup. Mapped credential failures raise a sanitized capability-local refusal rather than reading a stale environment/default. Frozen private-worker policy bypasses this mechanism and keeps its supplied scope.

`secrets.lazy_timeout_seconds` defaults to 5. A single monotonic context budget travels through the source-registry worker and CLI subprocess groups. No retry, alternate identity or extra plaintext credential cache is introduced. Existing source and host-wrapper caches/quotas retain their authority.

Launch-profile lazy reads retain the existing process-selected 1Password bootstrap authentication inputs, including a custom token variable and account/session/Connect settings. This narrow inheritance never applies to a foreign profile, never copies unrelated provider credentials, and does not publish values into the environment.

Tool availability probes treat configured but unresolved credentials as deferred: a truthy non-string presence object lets the predicate continue evaluating non-credential dependencies. Predicates requiring actual credential operations remain unavailable rather than bypassing those dependencies. Schemas remain subject to existing tool grants; the requested capability resolves its credential at execution. This is configuration availability, not authentication or reachability success. Administrator-managed credentials retain precedence over user mappings, and malformed/unreadable secret configuration refuses startup and credential reads rather than falling back to inherited values (including in otherwise eager profiles).

For optional MCP, use its existing `lazy: true` schema-cache mode. Lazy configurations retain unresolved environment references until the owning connection scope renders them, avoiding eager reads or freezing stale process credentials. `lazy_cold: defer` additionally prevents a missing schema cache from falling back to eager online discovery. Status reports the deferral; an explicit native reconnect invokes the existing lazy connection owner. A missing schema cache means tools cannot be advertised until that connection supplies schemas; no schema is invented. Default cold behavior is unchanged without the flag.

Fresh POSIX interactive clients have a 60-second startup budget from profile resolution through configuration and gateway attachment. Source subprocess limits and gateway ensure share the remaining allowance. Expiry raises a sanitized exit-78 refusal and unwinds Python cleanup; it never stops the shared gateway or changes provider. Once connected, the budget is retired (worker-loop attachment is observed by the main-thread timer). Existing daemon lifecycle watchdogs remain authoritative for servers. Kernel-blocked I/O and Python signal-delivery scheduling are not hard real-time guarantees. Windows does not use this POSIX timer.

TUI launchers first require the existing gateway readiness result within the remaining client budget, then hand off to the UI. Interactive first-run setup is considered a usable local UI and disarms the startup timer. This does not promise conversational use if inference or the gateway is unavailable.

Set the existing `security.allow_lazy_installs: false` for offline-controlled deployments; explicit package maintenance remains separate. Keep a system-Python, model-free runbook entrypoint outside Hermes so missing runtime dependencies cannot block recovery. Do not export vault caches or provision new recovery credentials when this diagnostic workflow needs none.

Bounded POSIX secret helpers run in an owned process group, killed on timeout/interruption. Source workers have a maximum one-second cleanup grace and are daemon threads so a non-cooperative Python plugin cannot pin interpreter exit. This does not sandbox arbitrary plugins or claim cancellation of external processes a plugin launches outside the supported helper. Existing source caches and quotas are not bypassed.

Qualification must distinguish synthetic source/credential adapters, real isolated-network CLI refusal, and installed-source acceptance. Source adoption alone does not opt a profile in.
